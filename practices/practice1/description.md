Итоговое практическое задание: анализатор расходов

JavaScript
Без сторонних библиотек
Уровень: средний+

Ты разрабатываешь небольшое ядро приложения для анализа личных расходов. На вход поступает список финансовых операций, а программа должна уметь рассчитывать статистику, фильтровать операции и создавать понятные отчёты.
Это не задача на знание финансов: вся логика сводится к работе с функциями и данными.
Ограничения:

- Используй обычный JavaScript.
- Не используй классы, async/await, промисы и сторонние библиотеки.
- Не изменяй исходный массив операций.
- Не применяй циклы for и while: используй изученные функции массивов и, где уместно, рекурсию.
- Не пиши всю программу в одной функции.
- Не добавляй абстракции без необходимости.
- Можно использовать стрелочные функции, обычные функции, map, filter, reduce, замыкания, rest/spread и деструктуризацию.

Задание A. Базовые вычисления
Реализуй функции:

1. getTotalAmount(transactions) — возвращает сумму amount всех переданных операций.
2. getTransactionsByType(transactions, type) — возвращает только операции указанного типа.
3. getTotalByType(transactions, type) — возвращает общую сумму операций указанного типа.
4. getTransactionsByCategory(transactions, category) — возвращает операции заданной категории.
5. getAverageAmount(transactions) — возвращает среднюю сумму операции. Для пустого массива верни 0.
   Важно: не дублируй одну и ту же логику без причины. Если одна функция может разумно использовать другую, подумай, стоит ли так сделать.
   Задание B. Отчёт по расходам
   Реализуй функцию:
   getExpenseReport(transactions)

Она должна возвращать объект с общей суммой доходов, общей суммой расходов, балансом и количеством расходных операций.
Ожидаемая структура:
{
totalIncome: 95500,
totalExpenses: 11150,
balance: 84350,
expenseCount: 7
}

Это пример формата результата. Тебе нужно самостоятельно реализовать вычисления.
Подсказка по смыслу: баланс — это доходы минус расходы. Возврат в исходных данных считается доходной операцией, поскольку именно так задано поле type.
Задание C. Статистика по категориям
Реализуй функцию:
getExpensesByCategory(transactions)

Она должна вернуть объект, в котором ключи — названия категорий, а значения — суммы расходов в соответствующей категории.
Для исходных данных результат должен иметь такую структуру:
{
Еда: 5650,
Транспорт: 3700,
Развлечения: 1800
}

Категории, в которых есть только доходные операции, включать не нужно. Если появятся другие категории с расходами, они тоже должны попасть в результат.
Это наиболее содержательная часть задания: подумай, какую роль здесь может сыграть reduce и как накапливать объект-результат.
Задание D. Функция-фильтр с замыканием
Создай функцию:
const createAmountFilter = (minAmount) => {
// твоя реализация
};

Она должна возвращать новую функцию, которая принимает одну транзакцию и возвращает true, если её amount больше или равен заданному минимуму.
Пример использования:
const isLargeTransaction = createAmountFilter(2000);

isLargeTransaction(transactions[0]); // true
isLargeTransaction(transactions[2]); // false

После создания фильтра порог должен сохраняться внутри возвращённой функции. Не передавай его повторно при каждом вызове.
Затем используй созданную функцию вместе с filter, чтобы получить все операции на сумму не менее 2 000.
Задание E. Цепочка преобразований
Реализуй функцию:
getLargeExpenseTitles(transactions, minAmount)

Она должна вернуть массив названий расходных операций, сумма которых не меньше minAmount.
Например, при пороге 2000 результат должен быть:
['Продукты', 'Бензин', 'Ресторан']

Требования:

- доходы не включать;
- операции, равные порогу, включать;
- вернуть только названия, а не целые объекты;
- использовать цепочку операций над массивом;
- не изменять исходные данные.
  Подумай, в каком порядке лучше применять фильтрацию по типу, фильтрацию по сумме и преобразование через map.
  Задание F. Разделение вычислений и побочных эффектов
  Создай две функции:
  formatExpenseReport(report)
  printExpenseReport(report)

Первая должна принимать объект отчёта и возвращать строку с читаемым отчётом. Вторая должна выводить эту строку в консоль.
Например, строка может выглядеть так:
Доходы: 95 500
Расходы: 11 150
Баланс: 84 350
Количество расходов: 7

Форматирование чисел необязательно делать через локализацию: можно просто соединить значения в строку. Главное — не смешивать формирование отчёта и его вывод.
